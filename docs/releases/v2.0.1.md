# pMax Performance Pack v2.0.1

A maintenance release on top of v2.0.0. No runtime, SQL, or deployment-ladder
behavior changes; the deployed image for v2.0.0 remains valid.

## What changed

- The trusted parity workflow (`.github/workflows/trusted.yml`) no longer
  ships. Public CI is fixture-only: it never requests an OIDC token, never
  federates to Google Cloud, and holds no credential. Real-data parity runs
  from the operator's deploy ladder (phase 80) and can be run by hand with
  `pmax-pack parity --source live`.
- The workflow contract tests assert the new shape: no federation, no
  `id-token` permission, pinned action SHAs, `pull_request` and `push` to
  `main` as the only triggers.
- Documentation updated to match: README, `docs/operations.md`,
  `deploy/iam.md` (the two probes that targeted the workflow principal are
  retired), and the runbook. The Workload Identity Federation pool the deploy
  ladder provisions is retained but unused until the operator removes it.
- Release process note: `main` is protected without a required review; every
  release still lands through a `release/vX.Y.Z` branch and a pull request
  with the fixture-only checks.

## Compatibility

Same requirements as v2.0.0 (Python 3.12, Google Ads API v25 pin).
