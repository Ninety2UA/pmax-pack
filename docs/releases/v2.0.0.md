# pMax Performance Pack v2.0.0

v2 turns the pack into an independently deployable Performance Max data
engine. It lands gaarf extracts in BigQuery, builds additive performance,
entity, best-practice, and cohort marts, and leaves a validation report after
every run.

## What shipped

- One private Cloud Run Job, deployed by immutable image digest with a numeric
  Secret Manager version.
- A paused-first Cloud Scheduler ladder. The first run, lease drill, parity,
  signed evidence review, rehearsal, alert proof, and resume happen in order.
- A GCS compare-and-set lease so one writer proceeds and a concurrent execution
  exits `SKIPPED` without advancing the latest report.
- Checkpointed extraction and window-bound transforms. Retries resume persisted
  chunks and rebuild every eligible click day in table-scoped transactions.
- An append-only observation log with Avro backup, plus run, stage, lease,
  checkpoint, parity, and report evidence in the operations ledger.
- Fixture-only pull-request CI with no Google Ads or GCP credentials. Protected
  real-data parity remains an operator execution that drops the scratch tables
  it creates.

## Cohort CPA and ROAS

Campaign and asset-group cohort cells use conversion-lag bucket prefixes.
Asset cohort cells use the cumulative value observed on click date plus cohort
day. The two readings keep separate provenance, maturity, and
`observed_through` values.

Action lookback windows cap every ladder. The window is always the final rung.
Missed asset observations may carry a prior non-seed value for at most five
days; longer gaps are unavailable. Cohort marts remain additive, while
`v_cohort_*` calculates CPA and ROAS after aggregation and excludes missing-cost
cells. See [the cohort contract](../cohorts.md).

## Fixed regressions

Three review rounds and their closing fixes covered these classes of defect:

- Packaging and execution: the pinned reference now ships with the installed
  package, bootstrap failures write structured evidence, and emergency reports
  target the writable report bucket.
- Data correctness: window-bound DML matures prior click days, account-scoped
  backfills preserve shared partitions, empty responses clear stale partitions,
  snapshot and account-local dates stay distinct, and cohort seed ordering is
  recoverable.
- Retry and concurrency safety: Ads API retries use production-scale backoff,
  long work renews the lease, lease budgets match task timeouts, execution
  adoption is keyed by mode and digest, terminal records clean up, and bounded
  polling tolerates transient describe failures.
- Evidence gates: parity is bound to the deployed digest and pinned reference,
  review evidence is checked against the ledger, rollback pointers are guarded,
  and the Scheduler cannot resume before the signed review and alert proof.
- CI and publish safety: dataset-reference linting catches wrong-layer SQL,
  deploy harnesses run on every pull request, scrub coverage includes nested
  and top-level record names, and public fixtures are proven anonymizer output.
  Main is protected by required review.
- Operator truth: run IDs stay time-sortable, dry-run reports say they are dry,
  CLI help and runbook behavior match the implemented union and two-pass gates,
  and validation queries carry their partition bounds.

No private account, project, billing, organization, or credential value is
part of this release.

## Upgrade outline

Use placeholders for every deployment value and inspect the plan first:

```bash
export PMAX_PROJECT_ID="your-gcp-project-id"
export PMAX_CONFIG_BUCKET="your-private-config-bucket"
export PMAX_CREDENTIAL_FILE="/secure/path/google-ads.yaml"

bash deploy/deploy.sh \
  --project "$PMAX_PROJECT_ID" \
  --region europe-west1 \
  --config-uri "gs://$PMAX_CONFIG_BUCKET/deployment.yaml" \
  --credential-file "$PMAX_CREDENTIAL_FILE" \
  --upgrade --plan
```

Never use `--yes`. Live human-owned phases require the operator's written
`PMAX_CONFIRMED_PHASES` or an interactive confirmation. Phase 85 may never be
listed there. `PMAX_SIGNED_REVIEW` is an operator-authored artifact bound to
persisted evidence; automation must not create or supply it.

Before an upgrade, pause Scheduler, record the observation row count, distinct
observed days, and latest observed day, confirm the rollback digest exists, and
complete the schema migration review so phase 25 receives
`PMAX_MIGRATION_REVIEWED=1`. Phase 70 rebuilds the live marts before the signed
review. Phase 88 separately rebuilds into the verification dataset. Compare
both reports, recheck the observation triple, prove the failed-execution alert,
then let the operator resume Scheduler.
